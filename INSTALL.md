# Installation and Usage

## Components not included in this repository

A fresh clone intentionally does not contain complete copies of the following
runtime components:

1. **Three `MPNN-ProGen2-xlarge-CATH42` safetensors shards (approximately
   13.1 GB).** See installation step 7, *Download the InstructPLM pretrained
   model*, to download exactly these three files into
   `MPNN-ProGen2-xlarge-CATH42/`: `model-00001-of-00003.safetensors`,
   `model-00002-of-00003.safetensors`, and
   `model-00003-of-00003.safetensors`. Download only these three shards; do
   not overwrite the complete model directory, because this repository
   contains modified model Python code. Verify the downloaded files against
   the three SHA256 values recorded in step 7.
2. **`cath43/` — the CATH 4.3 chain-level dataset package.** Download and
   extract it as described in the *Data preparation* section.
3. **`structure_embeddings_cath43/` — structure embeddings generated by
   `preprocess.py`.** Generate them as described in the *Data preparation*
   section.
4. **ESMFold runtime weights (approximately 8.45 GB).** fair-esm stores these
   files in the Torch Hub cache outside the repository. See installation step
   6, *Prepare the ESMFold model cache*.

The first three paths are expected to be absent or incomplete immediately after
cloning. Training cannot start until those components have been prepared. On a
networked system, fair-esm downloads the ESMFold runtime weights automatically;
offline preparation is described below.

## Installation

The verified environment uses Python 3.10, PyTorch 2.10.0 with CUDA 12.8,
Transformers 5.1.0, TRL 0.27.2, PEFT 0.18.1, Accelerate 1.12.0, and
fair-esm 2.0.0.

The commands below assume that the repository root is available through the
absolute path stored in `REPO`.

```bash
export REPO=/absolute/path/to/ProteinZero
```

### 1. Create the Python environment

```bash
conda create -n proteinzero python=3.10.19
conda activate proteinzero
python -m pip install --upgrade pip
```

### 2. Install the CUDA build of PyTorch

Install the CUDA 12.8 build before installing the remaining dependencies:

```bash
python -m pip install torch==2.10.0 \
  --index-url https://download.pytorch.org/whl/cu128
```

The verified runtime reports:

```text
torch.__version__ == "2.10.0+cu128"
```

The Python distribution metadata omits the local CUDA suffix and reports
version `2.10.0`.

### 3. Build OpenFold

ESMFold requires OpenFold, which is not distributed through PyPI. The verified
installation uses OpenFold v2.1.0 at commit:

```text
f434a2786b5a6b39171f358fb3470ad9f4fd2a58
```

Clone that revision and apply both required OpenFold patches:

```bash
git clone https://github.com/aqlaboratory/openfold
cd openfold
git checkout f434a2786b5a6b39171f358fb3470ad9f4fd2a58

patch -p1 < "$REPO/patches/openfold-v2.1.0-cxx17.patch"
patch -p1 < "$REPO/patches/openfold-v2.1.0-tuple-index.patch"

python -m pip install . --no-build-isolation
```

The `--no-build-isolation` option is required. pip 26 enables build isolation,
while OpenFold's `setup.py` imports PyTorch during the build. The CUDA PyTorch
installation must therefore remain visible to the build process.

The OpenFold revision referenced by fair-esm 2.0.0, revision `4b41059`, is not
usable with PyTorch 2.10. Its extension build fails with both C++14 and C++17,
and its `pytorch_lightning` imports are incompatible with the verified
environment.

### 4. Install the remaining Python dependencies

Return to the repository root and install the pinned dependencies:

```bash
cd "$REPO"
python -m pip install -r requirements.txt
```

### 5. Patch fair-esm

fair-esm 2.0.0 requires the supplied checkpoint-key remapping patch when used
with OpenFold v2.1.0. The following installation-path resolution command was
verified in a clean environment:

```bash
ESM_SITE_PACKAGES="$(
  python -c \
    'import esm; from pathlib import Path; print(Path(esm.__file__).resolve().parent.parent)'
)"

patch -p1 -d "$ESM_SITE_PACKAGES" \
  < "$REPO/patches/fair-esm-2.0.0-openfold-v2.1-key-remap.patch"
```

Verify the principal imports:

```bash
python -c "import torch, transformers, trl, peft, accelerate, datasets, esm, openfold"
```

### 6. Prepare the ESMFold model cache

On its first invocation, fair-esm downloads the ESMFold checkpoint, the
underlying ESM-2 language-model checkpoint, and the associated
contact-regression parameters. The files are obtained from the fair-esm public
file server and cached by Torch Hub:

- `esmfold_3B_v1.pt` — 2,771,653,574 bytes —
  https://dl.fbaipublicfiles.com/fair-esm/models/esmfold_3B_v1.pt
- `esm2_t36_3B_UR50D.pt` — 5,678,116,398 bytes —
  https://dl.fbaipublicfiles.com/fair-esm/models/esm2_t36_3B_UR50D.pt
- `esm2_t36_3B_UR50D-contact-regression.pt` — 6,759 bytes —
  https://dl.fbaipublicfiles.com/fair-esm/regression/esm2_t36_3B_UR50D-contact-regression.pt

The combined download size is 8,449,776,731 bytes (approximately 8.45 GB). No
manual action is required on a networked system. The first call to
`esm.pretrained.esmfold_v1()` downloads any missing files automatically.

Torch Hub stores these files under `$TORCH_HOME/hub/checkpoints`. If
`TORCH_HOME` is unset, it uses `$XDG_CACHE_HOME/torch/hub/checkpoints`; if both
variables are unset, the default is `~/.cache/torch/hub/checkpoints`. To select
another cache location, set `TORCH_HOME` before starting training:

```bash
export TORCH_HOME=/absolute/path/to/torch-cache
```

For an offline system, download the files on a networked system and place them
under the cache path that will be used at runtime:

```bash
TORCH_CACHE_ROOT="${TORCH_HOME:-${XDG_CACHE_HOME:-$HOME/.cache}/torch}"
CHECKPOINT_DIR="$TORCH_CACHE_ROOT/hub/checkpoints"
mkdir -p "$CHECKPOINT_DIR"

curl -fL \
  https://dl.fbaipublicfiles.com/fair-esm/models/esmfold_3B_v1.pt \
  -o "$CHECKPOINT_DIR/esmfold_3B_v1.pt"
curl -fL \
  https://dl.fbaipublicfiles.com/fair-esm/models/esm2_t36_3B_UR50D.pt \
  -o "$CHECKPOINT_DIR/esm2_t36_3B_UR50D.pt"
curl -fL \
  https://dl.fbaipublicfiles.com/fair-esm/regression/esm2_t36_3B_UR50D-contact-regression.pt \
  -o "$CHECKPOINT_DIR/esm2_t36_3B_UR50D-contact-regression.pt"
```

Verify the cached files:

```bash
sha256sum \
  "$CHECKPOINT_DIR/esmfold_3B_v1.pt" \
  "$CHECKPOINT_DIR/esm2_t36_3B_UR50D.pt" \
  "$CHECKPOINT_DIR/esm2_t36_3B_UR50D-contact-regression.pt"
```

The expected hashes are:

```text
e9a52579027e77d2d2e0a18218e755821f395730e86624cab9413dc117f5ca62  esmfold_3B_v1.pt
7de8b4082ba15891959ab368b77ce3886697af1efb16d3c9e9e7b0c5d3f07500  esm2_t36_3B_UR50D.pt
4da500eab246481dc9c8c95bc7b1d02f2803d761c380b0e95186d4a07d0fc84e  esm2_t36_3B_UR50D-contact-regression.pt
```

### 7. Download the InstructPLM pretrained model

The pretrained model is published at:

https://huggingface.co/InstructPLM/MPNN-ProGen2-xlarge-CATH42

The training launcher loads model files directly from:

```text
MPNN-ProGen2-xlarge-CATH42/
```

Download only the three weight shards. Do not download the complete model
snapshot over the release directory, because the repository contains revised
custom model code:

```bash
hf download InstructPLM/MPNN-ProGen2-xlarge-CATH42 \
  model-00001-of-00003.safetensors \
  model-00002-of-00003.safetensors \
  model-00003-of-00003.safetensors \
  --revision c525dffe95e4911ce18b0b870c81a0c019d65cc7 \
  --local-dir MPNN-ProGen2-xlarge-CATH42
```

Verify the downloaded files:

```bash
cd "$REPO"
sha256sum \
  MPNN-ProGen2-xlarge-CATH42/model-00001-of-00003.safetensors \
  MPNN-ProGen2-xlarge-CATH42/model-00002-of-00003.safetensors \
  MPNN-ProGen2-xlarge-CATH42/model-00003-of-00003.safetensors
```

The expected hashes are:

```text
7aaf74230b98697cd267b2135f00c9d9a0badaceee5d53bc9a68f790b036310a  model-00001-of-00003.safetensors
2de1bff26093acaa641f8b61c061d96acf090a4af47951bd768432a108326f37  model-00002-of-00003.safetensors
670f0b393f8a9f8560b40884120fa7fa09a09d46eda2f61fc30ecd8fbb1c1b17  model-00003-of-00003.safetensors
```

Their combined size is 13,108,612,812 bytes.

### 8. Bundled ProteinMPNN weights

No additional ProteinMPNN weight download is required.

The repository contains regular, self-contained weight files for the
ProteinMPNN encoders used by `preprocess.py`:

```text
ProteinMPNN/vanilla_model_weights/v_48_{002,010,020,030}.pt
ProteinMPNN/soluble_model_weights/v_48_{010,020}.pt
ProteinMPNN/ca_model_weights/v_48_{002,010,020}.pt
```

The ΔΔG scorer uses:

```text
ProteinMPNN/vanilla_model_weights/v_48_020.pt
```

These files are regular files rather than links to an external installation.
Their combined size is 59,959,839 bytes.

### 9. Install TM-align

TM-align is a required external executable. It is not a Python package and is
not bundled with this repository. The reward implementation invokes
`TMalign` by name, so the executable must be resolvable from `PATH`.

Bioconda installation:

```bash
conda install -c conda-forge -c bioconda tmalign=20220227
```

Source-build installation using the official source:

```bash
curl -L https://zhanggroup.org/TM-align/TMalign.cpp -o TMalign.cpp
g++ -static -O3 -ffast-math -o TMalign TMalign.cpp -lm
install -m 0755 TMalign /a/directory/on/PATH/TMalign
```

Omit `-static` on macOS or on systems without static libc.

Verify the installation:

```bash
command -v TMalign
TMalign -h
```

## ESMFold reproducibility

Reinstalling OpenFold and fair-esm through the procedure above does not
reproduce ESMFold outputs bitwise relative to the original verified
environment.

For the 71-residue native sequence of `2guzA`, the reinstalled environment
differed by one float32 ULP in mean pLDDT, and the maximum absolute difference
among atom37 coordinates was approximately `2e-05` Angstrom.

This coordinate difference is below the `1e-03` Angstrom coordinate grid of
the PDB format written before TM-align. It is therefore removed by PDB
serialization and does not affect TM-score or the downstream reward.

Within one fixed environment, repeated folds of the same sequence are bitwise
identical. This was verified for mean pLDDT, atom37 coordinates, and the
atom37 mask.

## Data preparation

Download the dataset archive from Hugging Face using the `hf` CLI:

```bash
hf download ZiwenWang28/cath43-chain-level \
  cath43_chain_dataset.tar.gz \
  --repo-type=dataset --local-dir .
```

Alternatively, download the archive directly:

```bash
curl -fL -o cath43_chain_dataset.tar.gz \
  https://huggingface.co/datasets/ZiwenWang28/cath43-chain-level/resolve/main/cath43_chain_dataset.tar.gz
```

Verify the archive before extraction:

```bash
sha256sum cath43_chain_dataset.tar.gz
```

The expected output is:

```text
fc555c10f0ebf77d788b6f457ea68bd64ce7c91a34769eccf66b1ea9060bfcc2  cath43_chain_dataset.tar.gz
```

Extract the verified archive:

```bash
tar -xzf cath43_chain_dataset.tar.gz
```

The extracted directory contains the 15 reference CSV files and `metadata.csv`
at its root, with PDB files under `pdbs/train`, `pdbs/val`, and `pdbs/test`.

The launcher expects the directory name `cath43`. Rename the extracted
directory:

```bash
mv cath43_chain_dataset cath43
```

This produces the paths used by the default launcher:

```text
cath43/train_data_le100.csv
cath43/val_data_le100.csv
cath43/pdbs/train/
cath43/pdbs/val/
```

### Generate structure embeddings

`preprocess.py` has the following command-line interface:

| Argument | Required | Default | Meaning |
|---|---|---|---|
| `--pdb_folder` | yes | none | Directory containing the input `*.pdb` files. |
| `--out_csv` | yes | none | Output preprocessing manifest. |
| `--out_pyd_dir` | yes | none | Directory for extensionless embedding pickle files. |
| `--skip_ca_only` | no | disabled | Omits the three Cα-only encoders. |

Run `preprocess.py` from the repository root. Its ProteinMPNN weight path is
relative to the current working directory:

```bash
cd "$REPO"
mkdir -p structure_embeddings_cath43
mkdir -p preprocessing_manifests

python preprocess.py \
  --pdb_folder cath43/pdbs/train \
  --out_csv preprocessing_manifests/train_embeddings.csv \
  --out_pyd_dir structure_embeddings_cath43

python preprocess.py \
  --pdb_folder cath43/pdbs/val \
  --out_csv preprocessing_manifests/val_embeddings.csv \
  --out_pyd_dir structure_embeddings_cath43

python preprocess.py \
  --pdb_folder cath43/pdbs/test \
  --out_csv preprocessing_manifests/test_embeddings.csv \
  --out_pyd_dir structure_embeddings_cath43
```

The three `--out_csv` files are preprocessing manifests. They do not replace
the released reference split CSV files.

By default, `preprocess.py` loads all nine bundled ProteinMPNN encoders and
writes one extensionless pickle file per structure identifier. Each pickle
contains:

```text
{"mpnn_emb": Tensor[L, 1152], "seq": str, "length": int}
```

The scripts originally used to aggregate CATH domain entries into chain-level
records and retrieve complete chains from RCSB are not included in this
release.

## Training usage

The formal default training configuration is:

- eight GPUs;
- CATH 4.3;
- the `le100` reference subset (sequences of at most 100 residues);
- LoRA rank 16 and LoRA alpha 16;
- 33,769,472 trainable parameters;
- 64 generations per prompt group;
- KL coefficient 0.1;
- diversity coefficient 0.05;
- TM-score and ProteinMPNN-derived ΔΔG reward weights of 1.0 each.

Launch the default configuration from the repository root:

```bash
cd "$REPO"
bash run_proteinzero_grpo.sh
```

The first positional argument selects the number of GPUs. It is not an
environment-variable override:

```bash
bash run_proteinzero_grpo.sh 8
```

The positional default is eight GPUs.

### Environment-variable overrides

The following table lists commonly used overrides and their defaults:

| Variable | Default |
|---|---:|
| `CATH_VERSION` | `4.3` |
| `TRAIN_SPLIT` | `le100` |
| `NUM_GEN` | `64` |
| `VAL_NUM_GEN` | `1` |
| `GENERATION_BATCH_SIZE` | `64` |
| `GRAD_ACC_STEPS` | integer result of `1024 / NUM_GPUS` |
| `NUM_TRAIN_EPOCHS` | `20` |
| `MAX_STEPS` | `-1` |
| `SAVE_STEPS` | `10` |
| `VALIDATE_EVERY_STEPS` | `10` |
| `LR` | `1e-5` |
| `LORA_RANK` | `16` |
| `LORA_ALPHA` | `16` |
| `KL_BETA` | `0.1` |
| `ALPHA_DIV` | `0.05` |
| `RW_TM` | `1.0` |
| `RW_DDG` | `1.0` |
| `SCALE_REWARDS` | `group` |
| `RUN_NAME` | generated |
| `RESUME_FROM` | unset |
| `DRY_RUN` | `0` |

When `VALIDATE_EVERY_STEPS` is greater than zero, the checkpoint save interval
is set to the same value, so setting `SAVE_STEPS` alone has no effect.

`NUM_GEN` controls the number of GRPO training rollouts per backbone.
`VAL_NUM_GEN` independently controls the total number of validation sequences
per backbone and defaults to one. Validation backbones are distributed across
ranks, so this count does not scale with the number of GPUs.

`NUM_GENERATIONS` appears only as a display label in launcher output. Setting
`NUM_GENERATIONS` has no effect.

The launcher validates the following relationships before starting Python:

- `GENERATION_BATCH_SIZE` must be divisible by
  `per_device_train_batch_size * NUM_GPUS`;
- `GENERATION_BATCH_SIZE` must be divisible by `NUM_GEN`;
- `GRAD_ACC_STEPS` must be divisible by
  `STEPS_PER_GENERATION * NUM_ITER`.

Example override:

```bash
TRAIN_SPLIT=101-300 NUM_GEN=64 LR=1e-5 bash run_proteinzero_grpo.sh 8
```

### Configuration-only validation

Set `DRY_RUN=1` to validate launcher arithmetic and configuration without
starting Python or allocating a training model:

```bash
DRY_RUN=1 bash run_proteinzero_grpo.sh 8
```

The default configuration has been verified on the `le100` subset. Other
subsets are subject to the pretrained-model constraints documented in
`DATASET.md`, which is included in the released dataset archive.
